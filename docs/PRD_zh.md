# 产品需求文档：Zen MCP 浏览器自动化

[English](PRD.md) | [简体中文](PRD_zh.md)

## 用户

- 需要检查或控制本地 Zen Browser 的 MCP 客户端。
- 需要稳定标签页、工作区、文件夹、网络和会话操作的 agent。
- 需要确定性本地构建、调试和发布流程的维护者。

## 用户故事

- 作为 MCP 客户端，我可以通过稳定的 `tabId` 检查和控制指定 Zen Browser 标签页。
- 作为 agent，我可以管理工作区、文件夹、置顶标签页、网络会话和会话拥有的浏览器资源。
- 作为维护者，我可以通过 WebSocket、HTTP 和本地调试前端使用同一套注册工具。

## 产品需求

### 浏览器自动化

- 导航、刷新、创建、关闭、列出和明确选择标签页。
- 检查页面结构、可见文本、表单字段和截图。
- 点击、填充、选择、勾选、按键、滚动、执行 JavaScript、等待和等待页面内容。
- 通过 `tabId` 定位页面操作，并可校验 `workspaceId` 和 `expectedUrl`。

### 搜索

- 支持 Google、Bing、DuckDuckGo、arXiv、bioRxiv、PubMed 和 Google Scholar。
- 支持带 `{query}` 和 `{page}` 占位符的自定义 HTTP(S) 搜索地址。
- 返回解析后的 URL、最终 URL、标题、可见文本，并关闭临时结果标签页。

### 工作区和 Zen 结构

- 列出和管理工作区。
- 列出和管理 Zen 文件夹及其成员关系。
- 独立列出和管理顶部置顶标签页、文件夹标签页和 essential 标签页。

### 网络和会话控制

- 捕获和检查特定标签页及 MCP 会话的请求。
- 过滤记录并读取有大小限制的请求和响应详情。
- 使用浏览器 Cookie 重放请求，并可覆盖重放响应。
- 在空闲清理后回收会话拥有的标签页。
- 使用带过期时间的会话锁串行化活动标签页操作。

### 传输和运行

- 通过 WebSocket 和 `POST /mcp` 提供相同的 MCP 权威。
- 保证并发客户端的响应隔离。
- 支持本地前台运行和可选的 Linux systemd user service。

## 非目标

- 不提供托管服务、认证层或远程浏览器控制。
- 不提供 zen-mcp 自有的持久数据库。
- 不提供公开 MCP 事件订阅 API。
- 不提供 DevTools Console 历史工具。
- 不支持单个 bridge 内的多窗口路由或多个浏览器实例。
